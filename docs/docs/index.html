General

CLight is a Python command-line application and a lightweight framework that simplifies CLI app development and the package distribution process.

It scaffolds a project for you, registers it as a global command, gives it a shared cli helper library, and publishes it to PyPI from Local, GitHub or GitLab environments.

Why CLight

  • Simple structure. Commands live in one index file; custom modules live in their own folder.
  • One import file. Declare pip modules once and share them across the index and every module.
  • Automatic packaging. Dependencies are detected and setup.py is generated at publish time.
  • Three deployment strategies. Local, GitHub and GitLab.
  • Semantic versioning. Bump versions with clight version.

New here? Continue with How it works, then Installation.

How it works

How it works

Every project you create follows the same flow:

  1. Run clight new in an empty folder and fill out the form. CLight copies its skeleton into the folder and writes your answers to .system/sources/clight.json.
  2. CLight registers a <CMD>.bat alias in %USERPROFILE%\.clight, a folder that is added to your PATH.
  3. When you type your command, the alias calls clight execute, which loads your .system/index.py and runs the method that matches the sub-command.
  4. A method's return value is printed: a string ending in ! shows as an error, any other string as a success message.
<cmd> demo hello
   |
   v
%USERPROFILE%\.clight\<cmd>.bat
   |
   v
clight execute ".system/index.py" demo hello
   |
   v
index.demo("hello")  ->  printed as success or error

Because the alias goes through CLight, your project does not run with python something.py. Run your CMD alias instead.

GeneralInstallation

Installation

Install CLight from PyPI:

  1. Open CMD as administrator and run the command below, then restart CMD.
  2. Run clight to check the installation. It lists the available commands.
pip install clight
clight

On first run CLight adds its catalog folder to your user PATH and asks you to restart CMD. This is expected.

Create your first project

  1. Navigate to an empty folder using CMD.
  2. Run clight new and fill out the form.
  3. Add commands as methods in .system/index.py.
  4. Run your CMD alias, for example mytool demo hello.

ConfigurationProject structure

Project structure

A generated project keeps everything in a .system folder:

<project-root>/
├── .system/
│   ├── imports.py     all pip and custom-module imports
│   ├── index.py       your CLI commands
│   ├── modules/       custom modules (clight module <name>)
│   └── sources/       resources and clight.json
├── .gitignore
├── README.md
└── LICENSE            if you chose a license

Don't remove modules, sources, imports.py or index.py. CLight depends on them.

index.py

Every public method becomes a command. Files have three sections: Load, Main and Helpers. Keep the trailing # (args) - description comment on each def line, because it builds the help text.

from imports import *


class index:
    def demo(self, param=""):  # (param) - Test demo method with param
        if not param:
            return "Invalid param!"
        cli.hint(param)
        return self.__helper()

    def __helper(self):
        return jobs.test()

imports.py

Import pip modules only here. CLight scans this file at publish time to build install_requires.

from clight.system.importer import cli  # DON'T REMOVE THIS LINE

import os
import sys
from modules.jobs import jobs

To pin a version, comment it at the top of the file:

# import openai==0:28

import openai

If the pip package name differs from the import name, add the pip name as a comment and mark the real import with # !install:

# import soupsieve

from bs4 import BeautifulSoup  # !install

Publishing

PyPI only accepts a version number once, so bump it before each release: navigate to your project's root in CMD, run clight version, and choose the type of change.

Local

  1. In your project's root directory, run clight publish.
  2. The first time, enter your PyPI PYPI_USERNAME and PYPI_API_TOKEN.
  3. Choose whether to save them. If you do, provide a Password Key to encrypt them.
  4. Next time you will only be asked for the Password Key. Use clight pypidel to delete saved credentials.

GitHub and GitLab

Nothing to do except push your changes to the main branch.

Add PYPI_USERNAME and PYPI_API_TOKEN as repository secure variables in GitHub or GitLab.

Generated GitHub projects ship a workflow that skips deployment when the commit message contains [!deploy]. Use clight publish -t to test the package locally first.

Semantic versions

Versions follow MAJOR.MINOR.PATCH, with optional alpha, beta or rc pre-release stages. clight version asks for the change type, and you can also pass a number directly.
